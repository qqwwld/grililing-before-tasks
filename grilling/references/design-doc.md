# 设计文档格式

使用简洁、严谨、准确、清晰、通俗的语言，遵循项目现有的目录、文件命名和元信息规范，维护一份设计文档。

以下是正文骨架。
```markdown
## Goal
What the user ultimately wants to achieve.

## Current State
Relevant existing work, approaches and attempts, facts, conditions, and available resources.

## Constraints
Requirements, limits, trade-offs, and non-negotiable conditions.

## Output
What must be delivered, including important format or quality requirements.

## Success Criteria
Observable results that show the goal has been achieved.

## Blockers
Current obstacles, uncertainties, or gaps between the current state and the goal, including where the existing approach breaks down and the evidence for it.

## Execution Path
The recommended approach based on the user-confirmed information.

1. ...
2. ...
3. ...

## Key Decisions
Only decisions that materially affect execution.

- **Decision:** ...
  - **Reason:** ...

## Assumptions
Only assumptions that execution currently depends on.

- ...

## Open Questions
Only unresolved questions that could still materially affect execution.

- ...
```
